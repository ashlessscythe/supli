# Onsite / LAN deployment

Supli Mart runs fully on a local server. It needs **Node.js 20+** and **PostgreSQL 16** (bare-metal or Docker). No cloud database, object storage, or email SaaS is required for core inventory workflows.

Attachments are stored as Postgres blobs by default. Email (invites, password reset, reorder alerts) is optional — without `RESEND_API_KEY`, messages are logged and skipped.

---

## Choose a layout

| Layout | Postgres | App | Best for |
|--------|----------|-----|----------|
| **A. Docker DB + host app** | `docker compose up -d` | `npm run dev` / `npm start` | Day-to-day onsite, easy upgrades |
| **B. Full Docker** | Compose | Compose `--profile full` | Single-command appliance |
| **C. Bare-metal Postgres** | OS package (`postgresql`) | `npm start` + systemd | No Docker on the host |

All three use the same app code and the same `DATABASE_URL` shape:

```text
postgresql://supli:supli@localhost:5432/supli?sslmode=disable
```

(In full Docker, the hostname is `postgres` instead of `localhost` — Compose sets this for you.)

## Quick start (recommended)

```bash
cp .env.example .env
# edit NEXTAUTH_URL if clients will use a LAN hostname/IP, e.g. http://192.168.1.50:3000
# NEXTAUTH_SECRET is generated by the helper if still placeholder-like

chmod +x scripts/*.sh
./scripts/onsite-up.sh --docker-db --seed   # or --host-db --seed
npm run build && npm start
```

Or all-in-one containers:

```bash
./scripts/onsite-up.sh --full --seed
# → http://localhost:3000
```

## A. Docker Postgres + app on the host

```bash
cp .env.example .env
openssl rand -base64 32   # paste into NEXTAUTH_SECRET
npm install
npm run db:up             # docker compose postgres
npm run db:setup          # migrate + seed
npm run build && npm start
```

Stop DB: `npm run db:down`.

---

## B. Full Docker (Postgres + app)

```bash
cp .env.example .env
# set NEXTAUTH_SECRET (and NEXTAUTH_URL for LAN access)
npm run local:up
npm run local:seed
```

App listens on port **3000**. Stop: `npm run local:down`.

Compose file: [`compose.yaml`](../compose.yaml). Image: [`Dockerfile`](../Dockerfile).

## C. Bare-metal PostgreSQL

Install Postgres 16 from your OS (example: Ubuntu):

```bash
sudo apt update
sudo apt install -y postgresql postgresql-contrib
sudo systemctl enable --now postgresql
```

Create role + database:

```bash
chmod +x scripts/setup-postgres.sh
./scripts/setup-postgres.sh
# prints DATABASE_URL=postgresql://supli:supli@localhost:5432/supli?sslmode=disable
```

Then:

```bash
cp .env.example .env
# DATABASE_URL already matches the script defaults
openssl rand -base64 32   # → NEXTAUTH_SECRET
# For LAN clients: NEXTAUTH_URL=http://<server-ip>:3000

npm install
npx prisma migrate deploy
npm run db:seed           # optional demo users
npm run build && npm start
```

Or: `./scripts/onsite-up.sh --host-db --seed` then `npm run build && npm start`.

### systemd

After installing the app under `/opt/supli` (or adjust paths):

```bash
sudo useradd --system --home /opt/supli --shell /usr/sbin/nologin supli || true
sudo rsync -a --exclude node_modules --exclude .git ./ /opt/supli/
sudo -u supli bash -lc 'cd /opt/supli && npm ci && npx prisma migrate deploy && npm run build'
sudo cp deploy/supli.service /etc/systemd/system/supli.service
# ensure /opt/supli/.env exists with DATABASE_URL, NEXTAUTH_SECRET, NEXTAUTH_URL
sudo systemctl daemon-reload
sudo systemctl enable --now supli
sudo systemctl status supli
```

Unit file: [`deploy/supli.service`](../deploy/supli.service).

## Environment (onsite)

| Variable | Required | Notes |
|----------|----------|--------|
| `DATABASE_URL` | yes | Local Postgres; use `sslmode=disable` on LAN |
| `NEXTAUTH_SECRET` | yes | `openssl rand -base64 32` |
| `NEXTAUTH_URL` | yes | Public URL clients use (`http://localhost:3000` or `http://192.168.x.x:3000`) |
| `RESEND_API_KEY` / `EMAIL_FROM` | no | Omit on air-gapped hosts; email logs only |
| `SUPERADMIN_*` | no | Bootstrap superadmin on first boot |
| `SERVER_ACTIONS_ALLOWED_ORIGINS` | no | Extra hostnames if you terminate TLS on a reverse proxy |

See [`.env.example`](../.env.example).

---

## Firewall / LAN

- Open **TCP 3000** (or put Nginx/Caddy in front on 80/443 and proxy to 3000).
- Keep Postgres on **localhost** (or Docker bridge) — do not expose `5432` to the WAN.
- Set `NEXTAUTH_URL` to the URL browsers actually open (IP or hostname).
